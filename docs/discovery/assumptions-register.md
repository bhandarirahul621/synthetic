An **assumption** is something the plan depends on that we believe but have not proven. A **riskiest assumption** is one that would sink the plan if it were wrong *and* that we know least about. We test those first. A pilot runs the same logic: check the engines before you check the coffee machine.

## How to read this table

- **Risk if wrong (H/M/L):** how much of the plan breaks if the assumption is false. H = the product or the beachhead fails; M = a phase or a metric needs rework; L = a local adjustment.
- **Uncertainty (H/M/L):** how little evidence we have today. H = none; M = indirect evidence such as desk research; L = strong evidence.
- **Score = Risk × Uncertainty**, with H = 3, M = 2, L = 1 (maximum 9).
- **Tie-breaks for "test first":** (1) does it block other decisions? (2) can Phase 0 activities test it? Metrics that only a live beta can measure are scheduled for Phase 1–2, even when they score 9.
- **Test methods:** interview, survey, landing page (a simple web page that measures sign-ups for a product that doesn't exist yet), desk research (published sources), beta metric (measured in the Phase 1–2 product), benchmark (measured by `qa-evaluation-engineer`).
- **Status values:** Untested · Testing · Supported · Challenged · Rejected · Known issue.
- **"Explicit"** means the PRD marks it **[Assumption]**. **"Implicit"** means the PRD relies on it without saying so.

## How to update this register

1. After each weekly synthesis, change **Status** and add a one-line evidence note, e.g., "Supported — 7/10 (+), see interviews #3, #5, #8."
2. If an assumption is **Rejected**, tell product-strategist. The PRD section it came from must change, and the version must be bumped.
3. Add new assumptions as interviews reveal them (next free ID: A30).

**Key takeaway:** rank assumptions by "how badly it hurts if we're wrong × how little we know," then spend Phase 0 only on the few at the top.
