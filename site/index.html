Test data is still a bad trade-off

Copy production

Realistic, but it puts customer data in staging, laptops and vendor tools. Masking a few columns doesn't stop people from being re-identified through combinations of fields.

Hand-write fixtures

Safe, but unrealistic. Random values break joins, miss edge cases and don't look like your real distributions.

Wait for access

Data requests for ML training or vendor sharing can take weeks, and rare events like fraud are barely in the data anyway.

How it works

  1. 1

    Start from what you have

    Upload a SQL schema or dbt model, describe your data in plain English, or provide a sample to learn from.

  2. 2

    Preview, then generate

    See 100 rows in seconds, adjust rules and scenarios, then generate millions of rows with a fixed seed so every run is identical.

  3. 3

    Use it anywhere

    Download Parquet or CSV, push to Postgres, call it from CI, or let your AI coding agent request it over MCP.

What we're building

Relational by design

Parent tables before children, realistic rows per parent, and every declared constraint enforced, so joins and reports behave like production.

Reproducible in CI

Versioned recipes plus seeds give byte-identical output, so tests stay stable and failures can be reproduced.

Privacy evidence, not promises

Every dataset comes with a report: copied-row checks, distance to the closest real record, membership-inference testing, and a plain-English summary.

Built for agents and humans

Everything in the web app is also available through the API, the CLI and an MCP server, so your coding agent can fetch the data it needs.

Questions

Can I use Synthetic today?

Not yet. We're in the discovery stage, talking with teams to make sure we build the right thing. Waitlist members get early access first.

Is synthetic data automatically "anonymous"?

Not automatically, and anyone who says so should show their evidence. Synthetic data can still leak information if a model memorizes its source. That's why every dataset will come with measured privacy checks. Whether data counts as anonymous under GDPR, HIPAA or other laws is a legal judgment, so we give your privacy team evidence to review rather than a legal guarantee.

Do I have to upload real data?

No. You can generate data from a schema or a plain-English description alone. Learning from a sample is optional, for when you need closer statistical realism.

Which databases will you support?

Postgres first, then Snowflake, BigQuery, Databricks, MySQL and S3. Tell us what you use in the form above, because it shapes our priorities.
